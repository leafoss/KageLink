# KageLink 3.5.1 — Persistent logical combat target

[Português](KAGELINK_3_5_1_COMBAT_TARGET.md)

## Physical evidence

Videos `round_002_20260731_142626_16052.avi` and `round_003_20260731_143032_9892.avi` showed one opponent receiving several `track_id` values during the same fight. Horizontal effects, player overlap, motionless animations, scrolling and a full reset caused by a sustained scene spike also interrupted the lock.

## Previous architecture

```text
motion
→ Candidate
→ EntityTrack
→ _grid_target_id
→ combat decision
```

The active target was the visual ID itself. `CONTACT_MEMORY` and `CONTACT_REBIND` reduced short losses, but no separate logical identity existed.

## 3.5.1 architecture

```text
global detector
→ disposable visual tracks
→ persistent Combat Target
   ├── stable combat_target_id
   ├── replaceable current_visual_track_id
   ├── predicted position/velocity
   ├── recent appearance and size
   ├── confidence
   └── contact direction
→ PURSUIT or MELEE_LOCK decision
```

States:

```text
VISIBLE
CONTACT
OCCLUDED_PREDICTED
LOCAL_REBIND
LOST
```

A few frames with `RAW CANDIDATES = 0` no longer remove the target. A nearby compatible new track may be associated with the same `combat_target_id`.

## Local rebind

Default scoring uses:

```text
45% distance to predicted position
25% size and proportion
15% appearance
15% movement/direction consistency
```

Local search happens before global acquisition resumes. During `MELEE_LOCK`, distant candidates receive a strong penalty and cannot easily steal the target.

## Direction and movement

- `PURSUIT`: the existing short movement pulses, always followed by perception;
- `MELEE_LOCK`: cancels continuous pursuit and preserves contact direction;
- default dead zone: 12 px on horizontal and vertical axes;
- direction reversal requires three consistent observations;
- movement confirmation uses logical `combat_target_id`, not a disposable visual ID.

## Effects and scrolling

The tracker applies conservative configurable rejection reasons:

```text
TOO_HORIZONTAL
TOO_VERTICAL
MAP_BORDER
HUD_REGION
CAMERA_FLOW
```

Extreme effects are rejected before tracks are created. Existing camera compensation remains part of prediction and local rebind.

During active combat, `MAP_SAVE_RESYNC` becomes a soft visual resynchronization. The previous frame and grid alignment may reset, while tracker state, environmental memory and logical target identity are preserved.

## Diagnostic video

The per-round AVI now includes:

- Combat Target ID;
- Visual Track ID;
- state and confidence;
- age and time since last sighting;
- known and predicted positions;
- contact direction;
- `PURSUIT` or `MELEE_LOCK`;
- last command;
- rebind radius and best score;
- pending switch;
- RAW, filtered and rejected candidates;
- camera flow;
- dashed prediction box, rebind region, trail and rejection reasons.

Annotation runs after perception and never modifies the frame, tracks or decisions.

## Replay validation limitation

Both supplied AVI files already contain boxes, panels and text burned into the frames. Cropping the main panel does not restore the original RAW input and would contaminate perception. They were therefore used for visual review and timeline correlation, not as a definitive quantitative replay of the new detector.

Final comparison of losses, rebinds and direction changes requires new videos generated by the updated Setup.

## Preserved scope

This layer does not change:

- Dojo Trainer location or click;
- sparring dialog;
- chat-authoritative KO;
- HP, stamina or chakra reading;
- meditation or `V/Y` toggles;
- post-combat return;
- F12, Stop or key release.
